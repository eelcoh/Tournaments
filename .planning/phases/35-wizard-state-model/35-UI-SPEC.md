## Interaction Contract

These contracts are specified here because Phase 35 state changes directly drive
view-layer behavior (Phase 36 will implement the view; this documents the
interaction semantics the state model must support).

### Round Progression (WIZ-01)

Opening `BracketCard` always shows `LastThirtyTwoRound` (R32) first.
`currentActiveRound` scans bottom-up: R32 → R16 → QF → SF → Final → Champion.
Returns the first round that has fewer teams than `roundRequired`. Fallback when
all rounds complete: `ChampionRound`.

### Selection Isolation (WIZ-01, WIZ-02)

`addTeamToRound` modifies only the target round's field. No cascade into later
rounds. Pool membership validation is enforced by `canSelectTeam`:
- R32: group cap ≤ 3 per group
- R16: team must be in `lastThirtyTwo`
- QF: team must be in `lastSixteen`
- SF: team must be in `quarters`
- Final: team must be in `semis`
- Champion: team must be in `finalists`

### Deselection Cascade (WIZ-03)

`removeTeamFromAll` already strips team from all six round fields atomically.
This function is not changed in Phase 35; it is correct as-is.

### Forward Nav Guard (WIZ-04)

`isWizardComplete` checks all six rounds at capacity using unique-team count:
- `lastThirtyTwo`: 32 unique teams
- `lastSixteen`: 16 unique teams
- `quarters`: 8 unique teams
- `semis`: 4 unique teams
- `finalists`: 2 unique teams
- `champion`: Just _ (not Nothing)

"Ga verder" is enabled only when `isWizardComplete` returns True.
`update` processes `GoNext` unconditionally; the guard is view-side only.
